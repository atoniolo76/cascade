API reference

Types

This page is generated from cascade/models.py each time the docs build, so it matches the code. The web UI mirrors the same types in web/src/api/types.ts.

Types are Python annotations as written in the source. X | None means the field is always present and may be null. datetime is an ISO 8601 string in UTC. tuple[int, int, int] is a JSON array of three integers.

States#

TraceState#

valuemeaning
uploadingFiles are arriving. kernel_count and bytes grow on each scan, every 2 seconds.
processingThe upload is complete. The app is running the trace post-processor, unless the upload already has traces/kernelslist.g.
readyPost-processing produced traces/kernelslist.g. Runs can launch.
failedmetadata.json has status: "failed", or post-processing failed. error says which.

SimState#

valuemeaning
pendingCreated with the run. Waiting for the launcher.
launchingThe launcher is starting the sim's sandbox or process.
runningThe sim sent a running heartbeat.
lostNo heartbeat for CASCADE_HEARTBEAT_TIMEOUT_S. A later heartbeat brings it back.
succeededThe sim sent a succeeded heartbeat. Terminal.
failedThe sim sent a failed heartbeat, the launcher failed, or it stayed lost for 10 times the timeout. Terminal.
cancelledThe run was cancelled before this sim finished. Terminal.

RunState#

cascade/models.py
RunState = Literal["active", "succeeded", "partial", "failed", "cancelled"]
valuemeaning
activeAt least one sim has not finished.
succeededEvery sim succeeded.
partialEvery sim finished, at least one succeeded, and at least one did not.
failedEvery sim failed.
cancelledEvery sim finished, at least one was cancelled, and none succeeded.

RunState is not stored. run_state() in cascade/models.py derives it from the run's sim states each time a run is read.

Simulator calls#

Heartbeat#

fieldtypedescription
stateLiteral["running", "succeeded", "failed"]What the simulator reports. Send running while working and succeeded or failed once at the end.
exit_codeint | NoneYour process's exit code. Send it with the final heartbeat. default null
errorstr | NoneA short reason, with a failed heartbeat. default null

HeartbeatAck#

fieldtypedescription
stateSimStateThe sim's state after this heartbeat.
cancelboolTrue when main cancelled this sim; the simulator must stop.

LogChunk#

fieldtypedescription
seqintPer-sim, increasing; a repeated seq is ignored. at least 0
lineslist[str]Lines of simulator stdout, without trailing newlines.

StepTimelineUpload#

What a sim posts after step timing: cascade simulate and cascade compare output.

fieldtypedescription
simulateddict`cascade simulate` output (simulated_timeline.json), with steps and summary.
comparedict | None`cascade compare` output (compare.json) against the real timeline.

Events#

RunEvent#

cascade/models.py
RunEvent = SnapshotEvent | SimEvent | LogEvent | KernelEvent

One event on the run event stream. The type field says which model it is.

SnapshotEvent#

fieldtypedescription
typeLiteral["snapshot"]Always snapshot. default "snapshot"
runRunDetailThe run as it is at connect time.
kernelslist[KernelStat]Every sim's stats with `stats` emptied; full stats are ~30 KB each.

SimEvent#

fieldtypedescription
typeLiteral["sim"]Always sim. default "sim"
simSimSummaryThe sim after a change: state, heartbeat, progress or metrics.

LogEvent#

fieldtypedescription
typeLiteral["log"]Always log. default "log"
sim_idstrThe sim the lines came from.
lineslist[str]The new chunk, as the simulator sent it.

KernelEvent#

fieldtypedescription
typeLiteral["kernel"]Always kernel. default "kernel"
statKernelStatA kernel that just finished, with the full stats map.

Sim transitions#

SIM_TRANSITIONS lists every allowed move. The app ignores any other move, whether it comes from a heartbeat or from the app itself. The comment above it in the source says who makes each move.

Allowed sim transitions. Main owns pending/launching/cancelled/lost; heartbeats own the rest.
from ↓ to →pendinglaunchingrunninglostsucceededfailedcancelled
pending·✓···✓✓
launching··✓✓✓✓✓
running···✓✓✓✓
lost··✓·✓✓✓
succeeded·······
failed·······
cancelled·······

succeeded, failed and cancelled are TERMINAL_SIM_STATES. Nothing leaves them. Concepts draws the same table as a diagram.
