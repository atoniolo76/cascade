Getting started

Introduction

Cascade takes a trace of an ML workload captured on one real GPU and simulates it on other GPU configs, many copies at once. You trace once, then ask how the same kernels run on an H100, an H200 or a dozen replicas of each.

How it fits together#

Cascade has three parts. Each part runs in a different place, and they talk over S3 and plain HTTP.

  • Profiler. Runs your workload, such as a vLLM model, on a Modal H100 under Accel-Sim's NVBit tracer. It uploads each kernel's trace to the Cascade app while tracing is still running.
  • Cascade app. One Sail sandbox that receives traces over S3, gets them ready to simulate, launches runs, and shows everything in a web UI and an HTTP API.
  • Simulators. Each simulator is a fork of the app's sandbox, so it starts with the trace already on disk. It runs Accel-Sim against one GPU config and reports progress back to the app.

What works today#

Two things are still in progress, and they change what you see.

  • A default deploy runs a stand-in simulator, cascade worker --replay, which replays a recorded Accel-Sim log instead of simulating your trace. To simulate your trace, deploy with --base-image, --sim-cmd and --accelsim-dir pointing at an image that has Accel-Sim built in. See Deploy the app.
  • The profiler doesn't capture real hardware timing (real_timing.json) yet. Until it does, the real-against-simulated comparison shows simulated time only.
