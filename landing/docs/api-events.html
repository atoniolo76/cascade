API reference

Live events (SSE)

The run screen stays live through one server-sent event stream per run. You can subscribe to the same stream from a script.

Stream run events#

GET/api/runs/{run_id}/eventsbearer token or ?token=

Opens a text/event-stream. The first event is always a snapshot. After that the stream sends sim, log and kernel events as they happen, and a : keepalive comment after 15 seconds without one. The stream does not close when the run finishes.

Path parameters#

nametypedescription
run_idstrThe run's id, such as run-9f56e171af08.

Query parameters#

nametypedescription
token optionalstrYour CASCADE_TOKEN. Use it when you can't set headers, as with EventSource. If present, it is checked instead of the header.

Returns#

200 with a text/event-stream of RunEvent, one JSON object per data: line.

Errors#

statuswhen
401The Authorization header is missing, is not Bearer <token>, or the token is wrong.
404No run has this id.

Example#

bash
curl -N -H "Authorization: Bearer $CASCADE_TOKEN" \
  "$CASCADE_URL/api/runs/run-9f56e171af08/events"
python
import json
import os

import httpx

headers = {"Authorization": f"Bearer {os.environ['CASCADE_TOKEN']}"}
url = f"{os.environ['CASCADE_URL']}/api/runs/run-9f56e171af08/events"
with httpx.stream("GET", url, headers=headers, timeout=None) as resp:
    for line in resp.iter_lines():
        if line.startswith("data: "):
            event = json.loads(line[6:])
            print(event["type"])
js
// EventSource cannot send headers, so pass the token as a query parameter.
const url = `${CASCADE_URL}/api/runs/run-9f56e171af08/events?token=${encodeURIComponent(CASCADE_TOKEN)}`;
const events = new EventSource(url);
events.onmessage = (msg) => {
  const event = JSON.parse(msg.data);
  console.log(event.type);
};

Wire format#

Each event is one data: line holding one JSON object, followed by a blank line. The stream uses no event: or id: fields, so read the object's type to tell events apart.

text
data: {"type":"snapshot","run":{"id":"run-9f56e171af08","trace_id":"demo", ...}, "kernels":[]}

data: {"type":"sim","sim":{"id":"sim-70f1ae5fc7c6","state":"running", ...}}

: keepalive

The response sets Cache-Control: no-cache and X-Accel-Buffering: no, so proxies pass events through as they happen.

Events#

These events come from the captured run. Each shows the first event of its kind that the stream sent.

snapshot#

Always first. It holds the whole RunDetail as it is at connect time and every finished KernelStat so far, with each stats map emptied to keep the event small. Order and reconnects#

  • Events arrive in the order the app committed them, and the snapshot never overlaps an event that follows it. Apply the snapshot, then apply each event on top.
  • For one log chunk the order is log, then any kernel events it completed, then sim.
  • The app keeps up to 2000 unsent events per subscriber. A subscriber that falls further behind is disconnected. Reconnect and start again from the new snapshot. EventSource reconnects by itself.
  • The stream stays open after the run finishes. Close it when the run's state is no longer active.
