Deploy the app

scripts/deploy_sail.py builds the app's image, starts it in a Sail sandbox, and prints the two URLs you need: the app, and the S3 endpoint the profiler uploads to.

Before you deploy#

  • A Sail account and API key.
  • A Cascade token. Pick any long random string. The UI, the profiler and every sim use it.
  • For real simulation, a simulator image: a Docker image with Accel-Sim, its trace post-processor and your simulator entrypoint built in. Without one, the app runs the stand-in simulator.

Deploy with a simulator image#

To simulate your traces, pass the simulator image and tell the app where things are inside it.

bash
git clone https://github.com/atoniolo76/cascade.git
cd cascade
export SAIL_API_KEY=...
export CASCADE_TOKEN=$(openssl rand -hex 24)
uv run --extra sail python scripts/deploy_sail.py \
  --base-image <simulator-image> \
  --sim-cmd "<simulator command>" \
  --accelsim-dir <path to accel-sim in that image>

If the image keeps the post-processor somewhere other than <accelsim-dir>/util/tracer_nvbit/tracer_tool/traces-processing/post-traces-processing, add --postprocess-cmd. Bring your own simulator lists what the image needs.

Deploy with the stand-in simulator#

Leave the three flags out to try the UI and the API first.

bash
uv run --extra sail python scripts/deploy_sail.py

Without --base-image, --sim-cmd and --accelsim-dir, every sim runs scripts/fake_sim.py, which replays a recorded Accel-Sim log of BabelStream on an RTX 3070. It doesn't simulate your trace, and its numbers are the same for every trace. The image is plain ubuntu:22.04, so it has no post-processor. Upload traces that already contain traces/kernelslist.g, or they fail in processing.

What the script prints#

The script builds the image if needed, creates the sandbox, starts cascade serve in it, and waits for the app's port.

text
creating sailbox 'cascade-main' in app 'cascade' (builds the image if needed)
sailbox:  <sailbox id>
app:      https://<app url>
s3:       https://<s3 url>  (bucket cascade, prefix accelsim-traces, path-style, unsigned)
logs:     /data/cascade-serve.log inside the sailbox
urluse it for
app (port 8000)Open it in a browser and paste your token. The same URL serves the API.
s3 (port 9000)Pass it to the profiler as --s3-endpoint. Traces upload here, unsigned and path-style.

If CASCADE_TOKEN isn't set, the script makes one and prints it as token:. Save it, because the app accepts nothing else.

Script flags#

flagdefaultwhat it sets
--appcascadeThe Sail app to create the sandbox in. The script creates it if it doesn't exist.
--namecascade-mainThe app sandbox's name.
--base-imageubuntu:22.04The Dockerfile's BASE_IMAGE, the image the app is layered on.
--sim-cmdthe fake simulatorCASCADE_SIM_CMD, the command each sim runs.
--accelsim-dir/app/tests/fixtures/accelsimCASCADE_ACCELSIM_DIR. The default holds real Accel-Sim configs but no simulator.
--postprocess-cmdderived from --accelsim-dirCASCADE_POSTPROCESS_CMD.
--disk-gibSail's defaultThe app sandbox's disk limit. Sims fork this disk, so size it for your traces.

What's in the image#

The Dockerfile builds the web UI with Node 22, then layers the app onto BASE_IMAGE: rclone 1.76.0, uv with Python 3.12, the app at /app, and the Accel-Sim configs and logs from tests/fixtures. The app sandbox and every sim fork run this one image. Sail doesn't run the image's CMD, so the script starts cascade serve itself, with CASCADE_LAUNCHER=sail and your SAIL_API_KEY, which the app needs to checkpoint and fork itself.

The sandbox has auto-sleep turned off, so the app keeps running while sims report in.

Configuration#

cascade serve reads these environment variables. The table is generated from cascade/settings.py.

variabledefaultwhat it sets
CASCADE_TOKENrequiredThe shared bearer token. The UI and every sim send it. The app refuses to start without it unless CASCADE_NO_AUTH is set.
CASCADE_LAUNCHERlocallocal runs each sim as a subprocess of the app. sail forks a Sail sandbox per sim. deploy_sail.py sets sail.
CASCADE_NO_AUTHfalseLocal development only. Set to 1 to turn off the token check: the API accepts any request, /api/health reports auth: false, and the web UI skips its token screen. Never set it on a deployment someone else can reach.
CASCADE_ACCELSIM_DIR/opt/accel-sim-frameworkAccel-Sim checkout. The app reads GPU configs from gpu-simulator/gpgpu-sim/configs/tested-cfgs/*/gpgpusim.config under it.
CASCADE_S3_BUCKETcascadeThe bucket the profiler uploads to. It is a directory under $CASCADE_DATA_DIR/s3/.
CASCADE_DATA_DIR/dataWhere the app keeps cascade.db, the S3 bucket directory s3/, and scratch files in work/.
CASCADE_SIM_CMDnoneThe command each sim runs. On Sail it runs through a shell. Locally it is split into arguments and run without one. Without it, every sim fails at launch.
CASCADE_POSTPROCESS_CMD$CASCADE_ACCELSIM_DIR/util/tracer_nvbit/tracer_tool/traces-processing/post-traces-processingAccel-Sim's trace post-processor. The app runs it once per trace as <cmd> <trace>/traces -j <cpus>.
CASCADE_HEARTBEAT_TIMEOUT_S60Seconds without a heartbeat before a sim becomes lost. After 10 times this, a lost sim becomes failed.
CASCADE_RUN_S3trueWhether cascade serve starts rclone serve s3 next to the app. Set false to run the S3 endpoint yourself.
CASCADE_PUBLIC_URLhttp://127.0.0.1:8000The URL sims use to reach the app. Each sim gets it as CASCADE_MAIN_URL.
CASCADE_S3_PREFIXaccelsim-tracesThe key prefix traces live under. Each trace is <prefix>/<run_name>/.

cascade serve takes --host (default 0.0.0.0), --port (default 8000) and --s3-port (default 9000).

The S3 endpoint accepts anonymous reads and writes. Anyone with its URL can upload a trace. The app's API and UI need the token.
