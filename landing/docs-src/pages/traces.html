The app watches its bucket directory. A trace appears on the **Traces** screen as soon as its first file lands, and it's ready once the upload is complete and post-processed.

Follow a trace

Open **Traces** in the UI, or poll [List traces](api-traces.html#list-traces). Each trace moves through these states.

{{enum TraceState}}

Open a trace to see what it came from: the model, the layers, the prompts, the source GPU, the suggested config, and every traced kernel with its grid and block size. The kernel list fills in when the trace becomes `ready`.

When an upload counts as complete

The app scans `$CASCADE_DATA_DIR/s3///` every 2 seconds. It skips dotfiles, which covers rclone's in-flight `.rclone_temp_put_*` objects. The upload is complete when `metadata.json` exists and one of these holds.

  • `metadata.json` has a `files` list, and every listed file is on disk with the listed size in bytes. `scripts/upload_trace.py` writes this list.
  • There is no `files` list, every `traces/kernelslist_ctx_*` has a matching `traces/stats_ctx_*`, and the file tree hasn't changed since the previous scan. This is the case for the streaming profiler, which uploads `metadata.json` before its `traces/` files.

If `metadata.json` has `status: "failed"`, the trace goes to `failed` straight away, without processing.

Post-processing

The profiler uploads raw traces. Accel-Sim reads processed ones, `traces/kernelslist.g` and one `.tracez` per kernel. So the app runs the post-processor once per trace.

```bash $CASCADE_POSTPROCESS_CMD /traces -j ```

Its output goes to `$CASCADE_DATA_DIR/work/postprocess/.log`. If it exits non-zero, the trace fails with the exit code and the last 5 lines of that log. If it succeeds but leaves no `kernelslist.g`, the trace fails too.

An upload that already contains `traces/kernelslist.g` skips post-processing. The quickstart's stand-in trace works this way.

If the app restarts during post-processing, the trace stays `processing` and the post-processor runs again on the next start.

Disk space

Traces grow with the layers, tokens and forward passes you trace. A single small layer is tens of MB. Whole models with long prompts reach hundreds of GB. Processed files sit next to the raw ones, so plan for about 2.2 times the uploaded size on the app's disk, and pass `--disk-gib` when you deploy.
