`scripts/deploy_sail.py` builds the app's image, starts it in a Sail sandbox, and prints the two URLs you need: the app, and the S3 endpoint the profiler uploads to.

Before you deploy

  • A Sail account and API key.
  • A Cascade token. Pick any long random string. The UI, the profiler and every sim use it.
  • For real simulation, a simulator image: a Docker image with Accel-Sim and its trace post-processor built in. Without one, the app runs the stand-in simulator.

Deploy with a simulator image

To simulate your traces, pass the simulator image and tell the app where things are inside it.

```bash git clone https://github.com/atoniolo76/cascade.git cd cascade export SAIL_API_KEY=... export CASCADE_TOKEN=$(openssl rand -hex 24) uv run --extra sail python scripts/deploy_sail.py \ --base-image \ --sim-cmd "/app/.venv/bin/cascade worker" \ --accelsim-dir ```

`cascade worker` runs `/gpu-simulator/bin/release/accel-sim.out` on the trace with the sim's config. If the image keeps the post-processor somewhere other than `/util/tracer_nvbit/tracer_tool/traces-processing/post-traces-processing`, add `--postprocess-cmd`. [Bring your own simulator](simulator.html#what-the-image-needs) lists what the image needs.

Deploy with the stand-in simulator

Leave the three flags out to try the UI and the API first.

```bash uv run --extra sail python scripts/deploy_sail.py ```

Without `--base-image`, `--sim-cmd` and `--accelsim-dir`, every sim runs `cascade worker --replay`, which replays a recorded Accel-Sim log of BabelStream on an RTX 3070. It doesn't simulate your trace, and its numbers are the same for every trace. The image is plain `ubuntu:22.04`, so it has no post-processor. Upload traces that already contain `traces/kernelslist.g`, or they fail in `processing`.

What's in the image

The `Dockerfile` builds the web UI with Node 22, then layers the app onto `BASE_IMAGE`: rclone 1.76.0, uv with Python 3.12, the app at `/app`, and the Accel-Sim configs and logs from `tests/fixtures`. The app sandbox and every sim fork run this one image. Sail doesn't run the image's `CMD`, so the script starts `cascade serve --sims sail` itself, with your `SAIL_API_KEY`, which the app needs to checkpoint and fork itself.

The sandbox has auto-sleep turned off, so the app keeps running while sims report in.

Configuration

`cascade serve` reads these environment variables. The table is generated from `cascade/settings.py`.

{{settings}}

`cascade serve` takes `--host` (default `0.0.0.0`), `--port` (default 8000), `--s3-port` (default 9000) and `--sims`. `--sims local`, the default, runs each sim as a subprocess of the app. `--sims sail` forks a Sail sandbox per sim.

The S3 endpoint accepts anonymous reads and writes. Anyone with its URL can upload a trace. The app's API and UI need the token.
