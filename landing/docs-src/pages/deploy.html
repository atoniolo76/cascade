A workspace is your own Cascade app in your Sail account: the Sail app `cascade-` with one sandbox, `cascade-main`, that runs the app and forks a sandbox per sim. Create it from the browser, or with `cascade deploy` from a checkout.

Get started in the browser

Open [Get started](../start.html), pick a workspace name, and paste a Sail API key from the Sail dashboard. The page shows each step as it happens and ends with an Open my workspace link that logs you in, the token, the S3 endpoint and ready-made upload commands. Nothing to clone.

  • The key creates the workspace in your Sail account. Cascade doesn't store it. It is copied into the workspace, because the app needs it to checkpoint itself and fork sims.
  • The workspace boots the published image, `ghcr.io/atoniolo76/cascade:latest`, with the stand-in simulator. Set another public image under advanced.
  • Manage, at the bottom of the page, shows a workspace's status, pauses and resumes it, and deletes it.

Deploy from the command line

`cascade deploy` does the same from a checkout. It is safe to rerun: it finds the workspace's sandbox, resumes it if it's paused, and prints the same URLs and token again.

```bash git clone https://github.com/atoniolo76/cascade.git cd cascade export SAIL_API_KEY=... uv run --extra sail cascade deploy --workspace acme-lab ```

When the app answers, it prints what you need.

```text cascade-acme-lab: starting Cascade cascade-acme-lab: healthy sailbox: app: https:// s3: https:// (bucket cascade, prefix accelsim-traces, path-style, unsigned) token: open: https:///#token= logs: /data/cascade-serve.log inside the sailbox ```

Deploy with a simulator image

To simulate your traces instead of replaying the stand-in, build the app on top of a simulator image and tell it where things are inside it. `--from-source` builds this checkout's `Dockerfile` on Sail, which takes a few minutes the first time.

```bash uv run --extra sail cascade deploy --workspace acme-lab --from-source \ --base-image \ --sim-cmd "/app/.venv/bin/cascade worker" \ --accelsim-dir ```

`cascade worker` runs `/gpu-simulator/bin/release/accel-sim.out` on the trace with the sim's config. If the image keeps the post-processor somewhere other than `/util/tracer_nvbit/tracer_tool/traces-processing/post-traces-processing`, add `--postprocess-cmd`. [Bring your own simulator](simulator.html#what-the-image-needs) lists what the image needs. The simulator settings are written once, when the workspace is first created. To change them, delete the workspace and deploy again.

Without `--base-image`, `--sim-cmd` and `--accelsim-dir`, every sim runs `cascade worker --replay`, which replays a real Accel-Sim run of `facebook/opt-125m` on SM90_H100 (20 vLLM kernels, from `results/20261108-021007-opt125m-h100-accelsim/`). It doesn't simulate your trace, and its numbers are the same for every trace. The image is plain `ubuntu:22.04`, so it has no post-processor. Upload traces that already contain `traces/kernelslist.g`, or they fail in `processing`.

What's in the image

The `Dockerfile` builds the web UI with Node 22, then layers the app onto `BASE_IMAGE`: rclone 1.76.0, uv with Python 3.12, the app at `/app`, and the Accel-Sim configs and logs from `tests/fixtures`. CI publishes it to `ghcr.io/atoniolo76/cascade` on every push to `amani` that changes the app. The app sandbox and every sim fork run this one image. Sail doesn't run the image's `CMD`, so the deploy writes the app's settings, including your `SAIL_API_KEY`, to `/data/cascade.env` (mode 600) and starts `cascade serve --sims sail` with them.

The sandbox has auto-sleep turned off, so the app keeps running while sims report in. Pause it from Manage on [Get started](../start.html) when you aren't using it.

Configuration

`cascade serve` reads these environment variables. The table is generated from `cascade/settings.py`.

{{settings}}

`cascade serve` takes `--host` (default `0.0.0.0`), `--port` (default 8000), `--s3-port` (default 9000) and `--sims`. `--sims local`, the default, runs each sim as a subprocess of the app. `--sims sail` forks a Sail sandbox per sim.

The S3 endpoint accepts anonymous reads and writes. Anyone with its URL can upload a trace. The app's API and UI need the token.
