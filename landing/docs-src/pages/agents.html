Paste one prompt into your agent and it can work your Cascade app for you. It reads your traces, launches runs on the configs that fit, watches them finish, and explains the results.

Setup promptTells your agent how to authenticate, which routes to call, and how to report results.

What an agent can do

The agent works through the same [HTTP API](api.html) as the web UI. With the prompt, it can do these things.

  • Check traces. It lists them, waits for an upload to become `ready`, and reports a trace that `failed`.
  • Launch runs. It picks the GPU configs whose `arch` matches the trace's `trace_gpu_arch` and asks before it starts more than 4 sims.
  • Watch runs. It polls the run until every sim has finished and tells you the progress as it goes.
  • Pull results and comparisons. It reads per-kernel times from `/kernels`, real against simulated time from `/comparison`, and the full stats from `/results` when you ask for them.
  • Explain the numbers. It reports simulated time per config, the error against real hardware when the trace has real timing, the worst kernels by readable name, and why any sim failed.

The agent can't trace a workload. Tracing runs on a real GPU under the Modal profiler, outside the API. [Trace a workload](trace-a-workload.html) covers that part. Once the trace is in your app, the agent takes it from there.

A default deploy runs the stand-in simulator, which replays one recorded Accel-Sim run of OPT-125m on an H100 for every trace. The prompt tells the agent to say so when the numbers look like the stand-in's, so a report never passes them off as a simulation of your trace.

Set it up

  1. Put the app's URL and token in the agent's environment. Run this in the terminal you start the agent from, then start the agent. The prompt tells the agent to read the token from `$CASCADE_TOKEN` and never print it. ```bash export CASCADE_URL=https:// export CASCADE_TOKEN= ```

    The URL and token are the ones [Get started](../start.html) shows when your workspace is ready, or the `app:` and `token:` lines `cascade deploy` prints. Locally the URL is `http://127.0.0.1:8000`.

  2. Give the agent the prompt. Copy the [setup prompt](#the-setup-prompt) and paste it into the chat, or save it where your agent reads instructions, as [Set up your tool](#set-up-your-tool) shows.
  3. Ask for what you want. For example: ```text Which of my traces are ready? Simulate the newest trace on every config that matches it, one sim each, and compare them. Why did sims fail in my last run? ```

The setup prompt

The build generates the API, state and type sections of this prompt from `landing/docs-src/endpoints.py` and `cascade/models.py`, the same sources as the [API reference](api.html). It always matches the API these docs describe. If you saved a copy, copy it again after you update Cascade.

{{agent-prompt}}

The same prompt is at [agent-prompt.md](agent-prompt.md) as plain Markdown, and at [cascade-skill/SKILL.md](cascade-skill/SKILL.md) as a skill with `name` and `description` frontmatter.

Set up your tool

Each tool below can take the prompt pasted into a chat. To keep it across sessions, save it as a file the tool reads. The commands copy the files from a Cascade checkout. Run them from your project's root, and set `CASCADE` to the checkout's path.

Claude Code

Save the prompt as a skill. Claude Code loads it when a request matches the skill's description. Use `.claude/skills/` in your project, or `~/.claude/skills/` to have it in every project.

```bash mkdir -p .claude/skills/cascade cp "$CASCADE/landing/docs/cascade-skill/SKILL.md" .claude/skills/cascade/SKILL.md ```

To load it in every session instead, append the prompt to your project's `CLAUDE.md`.

```bash cat "$CASCADE/landing/docs/agent-prompt.md" >> CLAUDE.md ```

Codex

Codex reads `AGENTS.md` in your project's root, and `~/.codex/AGENTS.md` for every project. Append the prompt to either one.

```bash cat "$CASCADE/landing/docs/agent-prompt.md" >> AGENTS.md ```

Cursor

Save the prompt as a project rule in `.cursor/rules/`. This rule has a description, so the agent can pull it in when a request is about Cascade. Cursor's docs list the other ways a rule can apply.

```bash mkdir -p .cursor/rules cat > .cursor/rules/cascade.mdc <<'EOF' --- description: Drive the Cascade app API for traces, runs and simulation results alwaysApply: false --- EOF cat "$CASCADE/landing/docs/agent-prompt.md" >> .cursor/rules/cascade.mdc ```

Other agents

Paste the prompt at the start of the conversation. If your agent loads skills from `SKILL.md` folders, use [cascade-skill/SKILL.md](cascade-skill/SKILL.md). Otherwise, save [agent-prompt.md](agent-prompt.md) wherever your agent reads project instructions. Check your agent's docs for where that is.
